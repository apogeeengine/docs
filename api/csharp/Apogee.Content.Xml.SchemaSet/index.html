    Class SchemaSet¶

    Namespace: Apogee.Content.Xml
    Assembly: Apogee.Content.dll

    XSD, the parts content definitions need: checking XML against a schema and turning it into data (). A set is every .xsd file loaded into it (and the ones they include), so that a package can bring the schema of the definitions it adds, and the children it adds to an open element of another's.

    Supported: element and attribute declarations (type, ref for elements, default, fixed, use, minOccurs, maxOccurs), complexType with sequence, choice and all (the order of children is not checked; a choice's members each repeat as they say, so a choice repeated stands for any order), group and attributeGroup, complexContent and simpleContent extensions, any and anyAttribute, simpleType restrictions (enumeration, minInclusive, maxInclusive, minExclusive, maxExclusive, pattern, minLength, maxLength, length) and lists, the built-in types, annotation, and include/import of a file by its location (no namespaces: names are plain). Anything else is a that names it, so a schema never means less than it says.

    Decode(XmlNode, string?, string?)¶

    Checks node against the schemas and turns it into data. An element with a complex type is a record: its attributes (numbers, booleans and text by their types, a list type as a list), the defaults of the attributes it leaves out, and its child elements by name; a child that may repeat is a list; an element that holds nothing but one repeatable element (<units><unit/><unit/></units>) is that list; an element with a simple type is its value. Two conventions are read from an element's xs:appinfo: map (a container of <entry key="…"> items is a record by the keys; an item that has nothing but a key and a value gives the value) and defaults (the element left out is decoded as an empty one, so that the defaults of its attributes apply; a list left out is empty). An open element (xs:any) gives each child the global element <its name>.<child name> when the schemas have one, and keeps the others as they are.
